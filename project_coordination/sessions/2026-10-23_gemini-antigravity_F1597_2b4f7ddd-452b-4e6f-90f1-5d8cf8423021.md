## 2. Iterative PDAS Execution Adapter Contract (`mode1-pdas-iterative-v1`)

The new execution adapter addresses the fundamental tension between PBS batch accounting (which expects pre-known job artifacts) and active-set optimization (which generates runtime subproblems):

### 2.1 Seed Input Deck & Datacheck Binding
- A single static seed input deck (`seed_c5_continuation.inp`) defines the C5 receiver mesh (4,610 physical phase nodes, reference node 999999), material properties, step definitions, and initial state transfer conditions.
- The seed deck must pass an authentic Abaqus datacheck (`ANALYSIS DATACHECK COMPLETE`, exit code 0) prior to PBS submission, guaranteeing solver syntax and UEL compilation compatibility.

### 2.2 Deterministic Subproblem Generation Protocol
At each outer PDAS iteration $k$:
- Only boundary condition statements on Degree of Freedom 11 are altered:
  - Upper active bound $U_k$: Dirichlet BC $d = 1.00000000$.
  - Lower active bound $L_k$: Dirichlet BC $d = d_{\text{checkpoint}}$ (the mapped damage threshold).
  - Free set $A_k$: unconstrained phase-field degrees of freedom.
- All other deck sections (`*NODE`, `*ELEMENT`, `*USER ELEMENT`, `*MATERIAL`, `*STEP`, `*CONTROLS`) are completely immutable and byte-identical to the verified seed deck.

### 2.3 Compute-Node Iterative Driver & Ledger Accounting
- The PBS wrapper executes `pdas_cluster_execution_adapter.py` inside the compute node environment co-loading `gcc/11.4.0`, `intel/2024.2.0`, `abaqus/2023`, and `python/gcc/11.4.0/3.11.7`.
- For each subproblem iteration, the driver logs entry into `pdas_subproblem_ledger.json`:
  - `iteration`: integer iteration counter ($1 \le k \le 25$).
  - `subproblem_id`: unique identifier.
  - `input_deck_sha256`: SHA-256 of the generated subproblem deck.
  - `exit_code`: solver return code (must be 0).
  - `set_sizes`: counts of $(|U|, |L|, |A|)$, strictly summing to 4,610 nodes.
  - `set_changes`: $\Delta N_{\text{active}}$ from previous iteration.
  - `residual_inf_norm_A_kNmm`: $\|R_d\|_{\infty, A}$.
  - `strict_healing_count`: count of nodes with $\Delta d < 0$ (must be 0).
  - `strict_overshoot_count`: count of nodes with $d > 1.0$ (must be 0).
  - `rf2_kN`: reaction force at control node 999999.

### 2.4 Convergence & Safety Termination
- Active set invariance: $\Delta N_{\text{active}} = 0$ AND $\|R_d\|_{\infty, A} \le 1.0 \times 10^{-6}\,\text{kN/mm}$.
- Safety cap: if $k > 25$, the driver aborts with error diagnostic rather than entering infinite solver cycles.
