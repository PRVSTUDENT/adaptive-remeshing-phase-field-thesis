## 2. Technical Investigation & Precision Mechanism Proof

### 2.1 Float32 vs Float64 Precision Impact
- Single-precision float32 stores 24 bits of significand (~7.22 decimal digits). At crack-tip displacement magnitude $u_y \approx 1.35 \times 10^{-3}\,\text{mm}$, 1 ULPS is $2^{-33} \approx 1.164 \times 10^{-10}\,\text{mm}$.
- For an element size $h_e = 0.68\,\mu\text{m}$, this single-bit noise creates strain variation $\Delta \varepsilon \approx 1.7 \times 10^{-7}$ and strain-energy density fluctuation $\Delta \psi \approx 4.07 \times 10^{-6}\,\text{MPa}$.
- Double-precision float64 stores 53 bits of significand (~15.95 decimal digits). 1 ULPS at the same displacement is $2^{-62} \approx 2.17 \times 10^{-19}\,\text{mm}$.
- Irreducible float64 strain-energy density noise floor: $\Delta \psi_{\text{float64}} \approx 3.75 \times 10^{-13}\,\text{MPa}$, providing $> 10^6$ margin below the target $\Delta \mathcal{H} \le 1.0 \times 10^{-6}\,\text{MPa}$.

### 2.2 Abaqus ODB API Specification
- In Abaqus/Standard, `output_precision=full` enables 64-bit double precision field output in `.odb`.
- In the Abaqus Python ODB API:
  - `FieldValue.precision` returns `symbolicConstants.DOUBLE_PRECISION`.
  - When `precision == DOUBLE_PRECISION`, `FieldValue.dataDouble` provides the 64-bit array. Accessing `FieldValue.data` raises an explicit `OdbError`.
  - When `precision == SINGLE_PRECISION`, `FieldValue.data` provides the 32-bit array. Accessing `FieldValue.dataDouble` raises an explicit `OdbError`.
- `scripts/validation/extract_package148_iteration.py` was updated to handle both transparently:
  ```python
  def _field_data(v):
      from abaqusConstants import DOUBLE_PRECISION
      if getattr(v, "precision", None) == DOUBLE_PRECISION:
          return v.dataDouble
      return v.data
  ```
