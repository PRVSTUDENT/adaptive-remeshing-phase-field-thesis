## 1. Executive Summary

A comprehensive source code and pipeline audit was performed to determine whether the existing production phase-field UEL/UMAT and model-building infrastructure can support 3-node triangular continuum elements (`CPE3`/`CPS3`) generated by Abaqus native 2D adaptive remeshing.

**Key Finding**: The entire production pipeline is strictly **quadrilateral-only** (`CPE4` / 4-node `U1` / 4-node `U2`). Abaqus 2D native adaptive remeshing requires either `TRI + FREE` or `QUAD_DOMINATED + FREE + ADVANCING_FRONT` (which generates mixed triangle and quadrilateral meshes). Because the production UEL Fortran subroutines, layer generators, and validation contracts do not support 3-node triangular elements, Abaqus native adaptive remeshing cannot be directly applied without resolving this element shape incompatibility.

## 3. Reference Implementation & Abaqus Documentation Analysis

1. **Abaqus 2D Native Adaptive Remeshing Requirements**:
   - According to Abaqus Documentation (*SIMACAECAERefMap / mgnconcadaptivityelements.htm*), 2D adaptive remeshing supports:
     - `TRI` + `FREE`
     - `QUAD_DOMINATED` + `FREE` + `ADVANCING_FRONT`
   - Pure `QUAD` is **not** a supported 2D adaptive remeshing mesh control.
2. **Pandey & Kumar (2025) Literature Reference**:
   - In Pandey & Kumar (2025), 2D adaptive remeshing generates mixed meshes containing both linear triangular (`CPE3`) and quadrilateral (`CPE4`) elements in benchmark geometries (e.g. L-panel).

---

## 4. Scientific & Architectural Incompatibility

- **Conflict**: Abaqus native 2D adaptive remeshing generates mixed meshes (`QUAD_DOMINATED` $\rightarrow$ `CPE4` + `CPE3`), whereas the production UEL and layer-rebuilding pipeline assumes all elements are 4-node quadrilaterals (`CPE4`).
- **Conclusion**: F41R5 pure-`QUAD` meshing is a standalone mesh candidate, but **not yet compatible with Abaqus native adaptive remeshing**.

---

## 5. Proposed Architectural Options for Decision Gate

To resolve this incompatibility before submitting HPC jobs for adaptive remeshing, three distinct options are identified:

1. **Option A: Add Triangular Element Support to Production UEL/Pipeline**
   - Extend Fortran UEL subroutines to support 3-node triangular elements (`NNODE = 3`, 1-point or 3-point area-coordinate shape functions and Gauss quadrature).
   - Update input deck layer generators and state transfer scripts to handle mixed 3-node ($U1_{tri}, U2_{tri}, CPE3$) and 4-node ($U1_{quad}, U2_{quad}, CPE4$) element blocks.

2. **Option B: Post-Remeshing Triangle-to-Quad Conversion Stage**
   - Retain 4-node UEL subroutines.
   - Introduce a post-processing mesh conversion script that splits or converts any generated `CPE3` triangles into `CPE4` quadrilaterals prior to layer rebuilding.

3. **Option C: Custom All-Quadrilateral Refinement Route**
   - Abandon Abaqus native adaptive remeshing for this complex geometry topology.
   - Implement a custom Python-driven all-quadrilateral refinement workflow (e.g. quad splitting / subdivision) that preserves 100% `CPE4` elements.
