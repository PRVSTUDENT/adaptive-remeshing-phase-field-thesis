## 3. Provenance Discrepancy Resolutions

### A. Resolution of the 3,930-Row CSV vs 2,906-Element Pre-Analysis Discrepancy
* **Physical Origin of 3,930 Rows:** In earlier project records, Job `1379893.mmaster02` (`M2MISER1`) evaluated the pre-analysis linear elastic step on the **Stage-F4 Mode-II shear benchmark mesh** ($N_{\text{el}} = 3,930$). An extraction script recorded 1 centroidal value per finite element, yielding exactly $3,930$ CSV rows.
* **Physical Origin of 2,906-Element Mode-I Mesh:** The canonical Pandey–Kumar Mode-I pre-analysis mesh has $N_{\text{el}} = 2,906$ finite elements ($2,818$ CPE4 + $88$ CPE3). Direct inspection of `DEBUG_PRE.odb` in Abaqus Python confirms that `frame.fieldOutputs['MISESERI'].values` contains exactly **$2,906$ values** ($1$ scalar error value per element at location `WHOLE_ELEMENT`).
* **Reconciliation Verdict:** The 3,930-row extraction belongs to the Stage-F4 Mode-II shear mesh ($N=3,930$), while the 2,906 value count belongs to the canonical Mode-I pre-analysis mesh ($N=2,906$). There is zero contradiction.

### B. Resolution of the Job `1404373.mmaster02` Release Mapping

* **Reconciliation Verdict:** Both Abaqus 2022 and Abaqus 2023 were genuinely executed under PBS Job ID `1404373.mmaster02`. In contrast, Abaqus 2021 was executed in dedicated Job `1404968.mmaster02`, and Abaqus 2019 was executed under Native 2019 GA / Job `1405052.mmaster02`.
