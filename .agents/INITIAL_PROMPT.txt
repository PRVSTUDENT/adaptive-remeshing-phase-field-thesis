## 2. An important correction to our previous decisions

Earlier, we agreed:

> Strategy A only. Discard Strategy B.

That decision was appropriate when our immediate objective was reproducing Pandey and Kumar.

Following today's meeting, we should revise that restriction rather than retain it indefinitely.

The supervisor specifically expressed interest in sequential refinement as the crack advances.

However, there are three distinct numerical approaches:

Method A — Two-pass pre-refinement

Current baseline

Coarse simulation → MISESERI → one remeshing operation → fresh simulation from the initial state.

No state transfer is required.

Method B — Multiple load partitions, one remeshing operation

Divide loading into 1, 2, or 4 Abaqus steps → evaluate the preliminary solution → remesh once → fresh final simulation.

This allows us to study loading schedules, but does not constitute sequential remeshing.

Method C — Sequential adaptive remeshing

Load incrementally → evaluate the current error field → remesh → preserve the required solution state → continue loading.

This is the supervisor's proposed extension. Genuine continuation requires verified state transfer or another demonstrably equivalent continuation mechanism.

My recommendation is to retain Method A as the verified reference, investigate Method B first, and develop Method C as a separately gated thesis contribution.

This respects the supervisor's directions without prematurely replacing the existing methodology.

## 3. The new primary research goal

I propose replacing our previous narrow automation goal with the following:

## Proposed thesis implementation goal

Develop and evaluate a configurable Abaqus Python framework for adaptive mesh refinement in phase-field fracture simulations using native Abaqus error estimation and remeshing.

The framework shall support automated pre-refinement and investigate sequential refinement during crack propagation, without requiring the crack trajectory to be prescribed in advance.

Its effectiveness shall be assessed through fracture-response accuracy, mesh convergence, computational cost, robustness, and reproducibility.

Two distinct objectives must remain equally important:

Scientific accuracy

Correct force–displacement response, crack trajectory, damage localization, and energy evolution.

Computational efficiency

Lower total runtime, memory use, and unnecessary mesh refinement, including preprocessing and remeshing overhead.

A finer-looking mesh or a lower element count alone does not establish success.

## 7. Critical scientific questions to resolve

There are three particularly important questions.

Question A: When should the mesh be refined?

Our corrected Mode-I result demonstrates that the evaluation state strongly influences mesh localization.

We must investigate whether the final MISESERI field is sufficient or whether refinement should occur before complete stress relaxation.

Question B: Can we continue a fracture simulation after changing the mesh?

This is the biggest technical challenge.

For a history-dependent fracture formulation,

\[ d_{n+1}\geq d_n \]

must be preserved under the appropriate irreversibility convention.

Simply generating a new mesh and continuing the loading without transferring the required fracture and history variables is not a valid sequential continuation.

We could repeatedly replay the entire analysis from the undamaged initial state on a newly refined mesh as an exploratory alternative, but that is not equivalent to genuine incremental remeshing. We must keep the distinction explicit.

Question C: Is repeated remeshing computationally worthwhile?

The total cost must include every operation:

\[ T_{\mathrm{total}} = T_{\mathrm{solver}} + T_{\mathrm{remeshing}} + T_{\mathrm{state\ transfer}} + T_{\mathrm{pre/post}} \]

Not every method contains all these terms. State-transfer cost, for example, is absent in the ordinary two-pass workflow.

A lower element count does not guarantee a shorter total runtime.
